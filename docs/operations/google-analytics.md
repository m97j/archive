# Optional Google Analytics

GA4 is the site's long-term analytics service. The private HF activity Bucket, credentials,
retention workflow and inactive capture implementation remain available; this integration
never enables those purposes or trains a model.

## Deployment

Set `GA4_ENABLED=true`, `GA4_MEASUREMENT_ID=<the public G- measurement ID>` and
`NEXT_PUBLIC_SITE_URL=https://marchivej.vercel.app` in Vercel Production, then redeploy.
Missing configuration, Vercel Preview and a different browser origin do not load Google.
The measurement ID is public configuration, not an API secret. No Measurement Protocol
secret, service account, paid API or BigQuery export is needed.

## Google property settings

- Standard GA4 web stream; timezone Asia/Seoul. Accept applicable processing terms.
- Optional account sharing off, Google Signals off, granular location/device collection off.
- No Google Ads links or advertising consent. User-ID linking is not implemented.
- User/event retention: 2 months; reset on new activity off. Standard aggregate reports have
  a different retention scope; the 2-month setting is not a universal erasure promise.
- Enhanced measurement off. In particular, leave Page views > advanced > Page changes based
  on browser history events off. `send_page_view:false` alone does not disable that feature.
- Email redaction on; query redaction is extra protection, not a replacement for sanitization.

## Consent and measurements

A non-blocking banner offers equally available allow, decline and settings actions. Only a
separate explicit analytics opt-in loads gtag.js. The consent choice contains permission,
version and expiry in localStorage for at most 90 days, without an activity log or visitor ID.
GA itself uses its own cookie identifiers; this is not described as fully anonymous.
Basic Consent Mode keeps Google tags and pings blocked before permission or after refusal.
Advertising storage, advertising user data and advertising personalization remain denied.

Only server-marked public index pages and published documents can emit `page_view`.
The pathname must match its public marker; a previous streamed DOM cannot label a new route.
The page URL is canonical origin plus public pathname. Query/hash and external referrers are
excluded from page views and default engagement parameters. This intentionally reduces
campaign/referral attribution in favor of data minimization.

A single `scroll` event is emitted at the public document body's 90% point while visible,
with no dialog open. Google's standard session/engagement events may also be generated by
the tag. Search text, form interactions, outbound/download URLs and user-account IDs are
not instrumented. Do not add no-code copies of page_view or scroll: they would duplicate
measurements. No event needs to be marked as a key event initially.

Withdrawal synchronously disables measurement, clears GA cookies and queued work, then
reloads a page where the tag ran to discard the loaded runtime. Other tabs receive the
preference change. A failed preference write stays closed; if persisting withdrawal fails,
the current runtime remains disabled without reloading an old persisted permission.
Withdrawal does not retroactively erase data already received by Google. Handle deletion
requests separately through the operator and Google's applicable deletion tools.

## Verification

Unit tests cover no consent, refusal, redaction, navigation/remount deduplication, private
routes, expiry, storage failures, cookie removal and cross-tab withdrawal. Browser tests
intercept the Google tag and all measurement destinations, so test visits do not populate
the production property. Confirm production tag delivery with an isolated browser and
intercepted measurement requests before inspecting real consented visits in GA Realtime.
